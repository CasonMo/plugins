Peer Agents lets an agent start an independent agent in another registered project on the same Paseo host and send messages to other agents. It adds `list_peer_projects`, `create_peer_agent` and `send_peer_message`, with task and message cards linking the conversations. It requires Paseo 0.9.1 or newer, Node.js 22 or newer, and a `paseo` CLI on the daemon’s `PATH` that connects to the same daemon as the calling agent. For a nondefault daemon host or home, configure `PASEO_HOST` or `PASEO_HOME` in the daemon’s environment.

A created agent runs in a new workspace, using the caller’s provider and model unless overridden. Local isolation shares the selected project’s directory; worktree isolation creates a separate checkout. The new agent receives the creator’s ID so it can reply. `send_peer_message` can address any agent on that daemon by ID, including agents the plugin did not create, and delivers a prompt that the recipient can act on.

**Permissions and data.** The tools are injected and preapproved for new Claude, Codex and OpenCode sessions, so agents can create workspaces, launch agents and send messages without a separate human confirmation. Existing sessions need reloading to receive the tools. Pi and internal agent creation are excluded. Tasks and messages become agent prompts and are handled by the selected providers. The plugin uses the local CLI with the inherited environment and reads the provider parent’s process environment on Linux when needed to recover the calling agent’s ID. It does not read unrelated credential files or install additional software at runtime.

Cards display Markdown and automatically load HTTPS images linked in tasks or messages, so the client contacts those image hosts. External text links open only when selected. If launching an agent fails, the plugin archives the newly created workspace only when it can verify that no agent started; otherwise it keeps the workspace for inspection.
